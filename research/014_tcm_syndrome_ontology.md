# 014 · 中医证候本体（TCM Syndrome Ontology）

> 状态：理论层 v0.2（机读目录已落地 `src/tcm_ontology.py`，纯理论零 HRV）
> 目的：把 research/013 的 5 单证"网眼"扩成一张完整的中医辨证之网——八纲 / 五脏六腑 / 六淫病因三轴正交，覆盖 **80–100 临床常见证型**。
> **边界声明（必读）**：本本体是**中医辨证理论知识库**，不是 HRV 评分扩展。HRV（`tcm_hrv_estimator.py`）只能代理其中**极小子集**（确有自主神经/迷走神经证据者）。全量输出仍须称「基于 HRV 的中医证候倾向性评估」，**不得称诊断**。红线同 research/013 第 6 节。

---

## 0. 为什么要从 5 个"网眼"织成"网"

research/013 建立引擎可打的 5 个 HRV 代理轴（气血不足 / 肝郁气滞 / 脾虚 / 痰气互结 / 阴阳平衡），但真实中医辨证是一张**分层、多轴、可复合**的网，不是 5 个并列分数。把 5 个轴说成"中医"，本质是"HRV 相关映射"而非辨证。

本层把这张网织出来，作为**统一知识底座**：
- 审计层可对照任意证型校核引擎输出的合理性；
- 未来报告/UI 可基于"用户的 HRV 倾向"在网中高亮**相关**证型家族（标注 HRV 不可测，须面诊）；
- 执业医师审校时，有完整条目可逐条核对，不必从零列清单。

---

## 1. 三轴正交分类法（The Three Orthogonal Axes）

每个证型同时落在三轴上，交叉定位——这正是中医"辨证"的思维方式。

### 轴 1 · 八纲（Eight Principles，总纲）
`yin / yang / exterior / interior / cold / heat / deficiency / excess`
- 阴阳为总纲；表里定病位浅深；寒热定病性；虚实定正邪盛衰。
- 例：肝郁气滞 → `[excess]`（实）；脾虚 → `[deficiency, interior]`（虚、里）。

### 轴 2 · 五脏六腑（Zang-Fu organs，病位）
`心 肝 脾 肺 肾 胃 小肠 大肠 膀胱 胆 三焦`
- 每个证型标注受累脏腑系统，复合证型可跨多脏腑。
- 例：肝胃不和 → `[肝, 胃]`；脾肾阳虚 → `[脾, 肾]`。

### 轴 3 · 病因（Etiology）
六淫 `风 寒 暑 湿 燥 火(热)` ／ 七情 `喜 怒 忧 思 悲 恐 惊` ／ 饮食劳逸 ／ 病理产物 `痰饮 瘀血 结石 食滞` ／ 其他 `体质 久病` 等。
- 区分"外感"（六淫、疫疠）与"内伤"（七情、饮食劳逸、病理产物）。
- 例：肝火炽盛 → `[怒, 火(热)]`；食滞胃脘 → `[食滞, 饮食不节]`。

## 2. 证型组织（Organization of the Net）

全量目录见 `src/tcm_ontology.py::TCM_SYNDROME_CATALOG`（机读、带校验）。按大类：

| 大类 | 轴 | 条数 | 代表证型 |
|---|---|---|---|
| **脏腑辨证** | 五脏六腑 | ~52 | 肝郁气滞、肝阳上亢、心气虚、脾阳虚、痰湿阻肺、肾阳虚、肝胆湿热、脾肾阳虚… |
| **气血津液辨证** | 气/血/津液病理 | ~17 | 气虚、气滞、血瘀、血虚、气血两虚、痰证、饮证、阳水/阴水、内湿/内燥… |
| **外感/六淫/卫气营血/六经** | 表里+病因 | ~17 | 风寒表证、风热犯肺、暑湿、少阳证、卫分证、气分证、血分证、太阳/阳明/三阴… |

合计 **89 条**（持续可补至 100+，如补充更多兼证、妇科/儿科专科证型）。

每一项的字段（机读结构 `SyndromeCatalogEntry`）：
`id / name_cn / name_en / category / organ_system / eight_principle / etiology / differentiation_points(辨证要点) / tongue_pulse(舌脉) / patho(病因病机) / hrv_detectable / evidence / notes`

## 3. 关键合规：HRV 能织进"网"的只有一小撮

**这是本层最重要的专业判断。** 89 个证型里，HRV 有循证代理价值的仅约 **17 个**，集中在"自主神经/迷走张力"相关者：

| 证型 | HRV 代理证据 | 说明 |
|---|---|---|
| 肝郁气滞 | 中 | HRV↓、恢复慢、波动大（NRICM 2010） |
| 肝火炽盛 | 弱 | 交感偏亢 RHR↑ |
| 肝阳上亢 | 弱 | 交感张力高伴血压波动 |
| 心气虚/心阳虚/心血虚/心阴虚 | 弱 | 心主血脉，HRV 相关 |
| 心脉瘀阻 | 弱 | 心血管自主神经失调 |
| 脾气虚 | 中 | SDNN/HF↓、LF-HF↑、恢复慢（Olivera-Toro 2019） |
| 肺气虚 | 弱 | 自主神经张力低下 |
| 肾阳虚/肾阴虚 | 弱 | 整体机能/交感差异（难分阴阳） |
| 气虚 / 气滞 / 血虚 / 血瘀 | 弱–中 | 整体气机/循环 |
| 气血两虚 | 中 | RMSSD↓+RHR↑ |
| 痰证 | 弱–中 | 严重自主神经抑制（Yang 2008） |

**其余 ~72 个证型 `hrv_detectable = False`，`evidence = NONE`**——它们是网的一部分、审计与报告可引用，但**引擎绝不可据 HRV 给分**。舌苔黄腻、脉弦、胁胀、太息、面色、问诊情志等核心辨证依据，HRV 一项都代理不了。

> 红线重申：任何来自本体的"证候倾向"输出，必须显式标注该证型 `hrv_detectable` 状态；`False` 者须提示"需面诊/四诊合参"，不得作为健康决策依据。

## 4. 与引擎现状的关系（Relationship to Engine）

- `tcm_theory.py`：保留原 5 单证 `SYNDROME_SPECS` + `COMPOSITE_SYNDROMES`，仍是 `tcm_hrv_estimator.py` 实际打分用的权威源（HRV 证据已固化的轴）。
- `tcm_ontology.py`：本层新增的**全量知识网**，纯理论。引擎目前**不**用它对用户打分，仅作为：
  1. 审计对照表（验证引擎输出不越界）；
  2. 报告/UI 的"相关证型家族"高亮候选（标注 HRV 不可测）；
  3. 执业医师审校底稿。
- 未来若要把某些新证型接入打分，必须经"证据升级"——找到 peer-reviewed HRV 关联研究、把 `evidence` 从中/弱提升、再在 `tcm_theory` 建 spec，而非直接拿本体条目当分数。

## 5. 校验与可维护性（Auditability）

`src/tcm_ontology.py` 提供：
- `validate_catalog()`：查重、校验八纲/脏腑/病因取值落在受控词表、保证 `hrv_detectable → evidence != NONE`、辨证要点非空。测试 `tests/test_tcm_ontology.py` 调用它。
- `catalog_by_organ / by_principle / by_etiology / by_category`：三轴查询，供报告层。
- `hrv_detectable_entries()`：只返回引擎允许打的证型家族。
- `catalog_stats()`：总条数 / HRV 可测数 / 三大类条数，供 CI 报告。

受控词表（`EIGHT_PRINCIPLES` / `ZANG_FU_ORGANS` / `ETIOLOGY_FACTORS`）集中定义，新增证型只能从中取值，保证网不被随意污染。
